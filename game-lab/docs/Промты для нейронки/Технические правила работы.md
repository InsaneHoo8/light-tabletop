# Технические правила работы

Этот документ описывает, как устроена работа над игрой с технической стороны: где что лежит, как вносятся правки, как запускаются симуляции и документы. Он нужен, чтобы порядок не зависел от памяти конкретной беседы.

## Где что лежит

**`game-lab/arena/cards.js`** — все числа игры: двенадцать персонажей и двадцать четыре артефакта. У персонажа хранятся имя, мир, здоровье, урон обычной атаки, менталка, энергия, лимит руки способностей, лимит руки артефактов, ёмкость щита, текст пассивки и восемь способностей.

**`game-lab/arena/engine.js`** — правила и бот. Способности и артефакты описаны списками операций: нанести урон, вылечить, дать щит, снять энергию и так далее. Движок исполняет эти списки.

**`game-lab/arena/game-data.js`** — прослойка, через которую движок получает данные.

**`game-lab/docs`** — единственный источник текста документов в формате markdown. Структура папок повторяет папку игры.

**`game-lab/tools`** — генераторы документов, таблиц и отчётов.

**`game-lab/sim-data`** — машинные слепки прогонов в JSON. По ним собираются таблицы.

**`game-lab/patches.json`** — реестр патчей и номер текущего.

## Как вносятся правки

Числа и русский текст правятся **скриптами Node**, а не через PowerShell. PowerShell портит кириллицу в своих строках и ломает JS-код при экранировании.

Перед записью файла скрипт обязан найти шаблон замены и упасть с ошибкой, если шаблон не найден. Молчаливая запись без проверки запрещена.

Файлы движка содержат переводы строк `CRLF`, поэтому перед поиском многострочных фрагментов текст нормализуется заменой на `LF`.

## Как проверяется движок

```
node game-lab/arena/tools/self-check.mjs
```

Должно быть «Все проверки пройдены». Если проверка падает — правка не готова.

## Как запускается симуляция

```
node game-lab/tools/sim-report.mjs <партий> <игроков> <папка игры> [описание эксперимента]
```

Например: `node game-lab/tools/sim-report.mjs 1500 4 "C:\...\Лайтовая настолка" "у Мирай двадцать пять здоровья"`.

Отчёт ложится в `game-lab/docs/Симуляция игр ботяр`, документ Word — в папку игры, машинный слепок — в `game-lab/sim-data`.

Внутри всегда вызывается `E.runBotsPick(s, -1)` после `newGame`, иначе партия стоит на фазе выбора руки.

**По умолчанию каждый бот в каждой партии заново выбирает стиль: агрессивный, пассивный или обычный.** Это стандартный режим замеров. Любой другой режим задаётся переменными окружения ниже.

## Режимы ботов через переменные окружения

- `AGGRO=1` — все боты максимально агрессивны.
- `CAUTION=1` — все боты максимально осторожны.
- `MIXED=1` — двое агрессивных, двое осторожных, порядок случайный.
- `STYLES=aggro,caution,normal,random` — стили по местам. Допустимые значения: aggro, caution, normal, random, hoarder, hoarder3, cycle5.
- `PRIORITY=1` — строгий порядок действий: артефакт, взятие, способность, обмен, атака.
- `PREFER_EXTRA=1` — приоритет картам с дополнительным действием.
- `PREFER_SHIELD=1` — приоритет картам со щитом.
- `COUNTERS=1` — бот учитывает чужие артефакты и способности.
- `NO_ART_LIMIT=1` — снять ограничение руки артефактов.
- `ESSENCE=текст` — своё начало имени файла отчёта.

## Как называются отчёты

Имя начинается с сути прогона, потом через тире идёт полное старое имя:

**«Стили ботов двое агрессивных, двое осторожных — Симуляция 0.0.4 15-11-2026 18-45-10»**

Суть подставляется автоматически: «Стили ботов…» для прогонов со стилями, «Поведение…» для приоритетов, «Патч…» для базовых замеров. Для разовых правок персонажей пишется «Эксперимент…» вручную через `ESSENCE`.

## Как собираются таблицы

**Мета-данные** — `node game-lab/tools/make-meta-xlsx.mjs <куда.xlsx> <слепок.json> [ещё слепки]`. Двенадцать персонажей в строке, под каждым столбец способностей и столбец артефактов. Под способностями Эт’Коры отдельная строка «Ворованные способности».

**Винрейты по стилям** — `node game-lab/tools/make-winrate-xlsx.mjs <куда.xlsx> <слепок.json> [ещё слепки]`. Один персонаж — один столбец, четыре строки: имя, агрессивный, пассивный, обычный, плюс нижняя строка с общим винрейтом. Таблицы лежат в подпапке «Винрейты» папки «Мета-данные симуляции».

## Как собираются документы Word

Исходники — markdown. Сборка всех документов сразу:

```
node game-lab/tools/md2docx.mjs sync "C:\Users\InsaneHoo8\Desktop\Лайтовая настолка"
```

Числа в тексте пишутся словами, шрифт Times New Roman, знаки решётки в текст не попадают.

Документы в папке игры не пересобираются без прямой просьбы.

## Известные ловушки

**PowerShell и кириллица.** Любой русский текст в команде PowerShell может прийти искажённым. Только Node-скрипты.

**Общие объекты карт.** Способности в данных — общие объекты для всех партий. Если пометить карту изменением, метка останется навсегда. При краже карта копируется.

**Занятый файл Word.** Если документ открыт, пересборка падает с ошибкой доступа. Нужно закрыть файл и повторить.

**Двойной сброс артефактов.** У артефактов два сброса: старый доступен для добора, новый заперт. У способностей такая же схема на уровне игрока.

## Порядок работы с правками

1. Правка вносится в данные или движок скриптом с проверкой шаблона.
2. Запускаются проверки движка.
3. Если менялись правила — обновляются исходники документов в `game-lab/docs`.
4. Запускается симуляция, цифры сообщаются словами.
5. Документы в папке игры пересобираются только по прямой просьбе.
6. Новый номер патча ставится только на устойчивое изменение, эксперименты помечаются в шапке отчёта.
